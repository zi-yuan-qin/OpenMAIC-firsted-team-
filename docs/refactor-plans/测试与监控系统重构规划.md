### 1.2 关键缺口

| 缺口 | 严重程度 |
|------|---------|
| **无编排层集成测试** (director-graph.ts, stateless-generate.ts 零覆盖) | 🔴 高 |
| **无生成管线集成测试** (端到端: 大纲→内容→动作) | 🔴 高 |
| **无聊天端点集成测试** (POST /api/chat) | 🟡 中 |
| **无课堂 CRUD 测试** | 🟡 中 |
| **无性能监控** (生成时间/LLM延迟/token消耗不追踪) | 🔴 高 |
| **无错误追踪聚合** | 🟡 中 |
| **健康检查不验证连接** (只统计配置数量) | 🟡 中 |
| **无环境变量校验** (启动时不检查必填项) | 🟡 中 |

### 1.3 监控/日志现状

**logger.ts**: 简单的分级日志（debug/info/warn/error），支持 text/json 格式。无性能计时、无 token 追踪、无错误聚合。

**健康检查** (`app/api/health/route.ts`): 仅返回静态 provider 数量。不主动探测各提供商连接状态。

**Docker**: 4 阶段构建(基础→依赖→构建→运行)，较优。缺 dev 版本。

## 2. 重构目标

### 2.1 核心原则

1. **补测试缺口**: 编排层+生成管线+聊天端点的集成测试
2. **可观测**: 性能计时 + LLM 响应追踪 + token 消耗统计
3. **可诊断**: 健康检查增强 + 环境变量验证
4. **轻量**: 不引入重量级依赖（不用 Sentry），用现有 logger 扩展

### 2.2 验收标准

- [ ] 编排层单元测试通过（director-graph, prompt-builder, stateless-generate）
- [ ] 生成管线集成测试通过（端到端: outline→content→actions）
- [ ] 聊天端点集成测试通过（POST /api/chat 的 SSE 响应）
- [ ] 课堂 CRUD 测试通过
- [ ] 性能监控可用：追踪生成时间、LLM 响应时间、token 消耗
- [ ] 错误追踪可用：按 endpoint 聚合错误率
- [ ] 环境配置验证器可用：启动时检查必填环境变量
- [ ] 健康检查增强：验证各提供商连接状态（非阻塞）
- [ ] Docker 多阶段构建可用 + dev 版本

### 3.3 性能监控设计

```typescript
// performance.ts
interface PerformanceTimer {
  start(label: string): void;
  end(label: string): PerfRecord;
}

interface PerfRecord {
  label: string;
  durationMs: number;
  tokensUsed?: number;
  model?: string;
}

interface LLMCallMetrics {
  model: string;
  promptTokens: number;
  completionTokens: number;
  durationMs: number;
  source: string; // 'scene-content', 'chat', etc.
}

class PerformanceMonitor {
  // 计时
  time<T>(label: string, fn: () => Promise<T>): Promise<{ result: T; durationMs: number }>;
  // LLM 调用追踪
  recordLLMCall(metrics: LLMCallMetrics): void;
  // 获取统计
  getStats(): { avgDurationMs: number; totalCalls: number; totalTokens: number; bySource: Record<string, PerSourceStats> };
}
```
