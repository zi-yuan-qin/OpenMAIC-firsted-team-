## 1. 当前系统分析

### 1.1 现状概览

智能体注册表位于 `lib/orchestration/registry/`，基于 Zustand + localStorage/IndexedDB 双存储。B-001 已将其部分英文化（人名+persona），但核心架构仍是"6 个硬编码对象"模式。

### 1.2 当前目录结构

```
lib/orchestration/registry/
  types.ts              # AgentConfig, AgentTemplate, ROLE_ACTIONS
  store.ts              # Zustand store, DEFAULT_AGENTS (6个硬编码)
  index.ts              # ❌ 不存在
```

### 1.3 核心问题

1. **硬编码**: `DEFAULT_AGENTS` 6个完整 JSON 对象写死在 `store.ts`，无法扩展
2. **agent-profiles API prompt 硬编码**: system/user prompt ~60行手写字符串，没用 B-001 模板
3. **工厂函数未使用**: `createAgentFromTemplate()` 定义后从未被调用，创建逻辑分散重复
4. **无组合规则**: 角色搭配全靠 LLM 自由发挥，质量不稳定
5. **存储不完整**: IndexedDB `GeneratedAgentRecord` 不持久化 `voiceConfig` / `personaType`
6. **UI 不完整**: agent-config-panel "新建"/"编辑"按钮无事件处理

### 1.4 Agent 生命周期

```
创建路径:
  1. 默认 → DEFAULT_AGENTS → Zustand store
  2. LLM → /api/generate/agent-profiles → IndexedDB + Zustand
  3. 服务端 → classroom-generation.ts → Stage 对象
  4. 自定义 → addAgent() (无 UI 入口)

存储:
  - 默认: 代码定义, Zustand 初始态
  - 自定义: localStorage (key: agent-registry-storage, v11)
  - 生成: IndexedDB (generatedAgents) + Zustand 临时

消费端:
  - 内容/动作生成 → formatTeacherPersonaForPrompt / formatAgentsForPrompt
  - 运行时编排 → buildStructuredPrompt (role + persona 模板)
  - 圆桌 UI → agentsToParticipants
  - 导演路由 → resolveAgent
```

4. **组合规则**: 角色搭配推荐引擎
5. **存储完整**: voiceConfig + personaType 持久化

type ComboRule = {
  id: string; name: string; description: string;
  appliesTo: (courseInfo: CourseInfo) => boolean;
  recommendedCombo: {
    teacher: 1;
    assistant: number;
    students: { count: number; preferredTypes: string[] };
  };
};

const DEFAULT_RULES = [
  { id: 'standard', name: '标准课堂', appliesTo: () => true, combo: { teacher:1, assistant:1, students:{count:3, preferredTypes:['curious','analytical','note-taker']} } },
  { id: 'workshop', name: '动手实践', appliesTo: (c) => hasInteractive(c), combo: { teacher:1, assistant:2, students:{count:3, preferredTypes:['creative','curious','analytical']} } },

];
